## 3. Notes on difficulties encountered

These notes apply across all 3 documents in this submission (the difficulties were common to all of them):

- All 3 documents are Madhya Pradesh e-registration 'Panjiyan Praman Patra' sale deeds (हस्तांतरण-पत्र). docA has 27 pages, docB has 22 pages, docC has 37 pages -- every page of all 3 documents is transcribed in this ground truth (full-document coverage).
- docA and docC are born-digital PDFs (Devanagari CID TrueType font embedded) with a genuine text layer. Text was extracted using pdftotext -layout, which preserves visual top-to-bottom reading order (the default and -raw modes were tested and found to follow the PDF's internal content-stream order instead, which does not match the visual layout). A cleaning pass removes duplicate paragraphs and repeating line-cycles that these PDFs store internally multiple times (2 to 42 repeats observed) even though the content renders only once visually -- confirmed by manually inspecting rendered page images at multiple points.
- docB is a true photographed/scanned document (pdffonts shows zero embedded fonts) -- ground truth for all 22 pages was built by manually viewing and transcribing each rasterized page image, since no text layer exists to lean on.
- Complex multi-column tables (e.g. docA/docC page 15, the khasra ownership-share tables) are transcribed completely and accurately in content, but plain-text extraction tools do not reliably preserve left-to-right, top-to-bottom reading order for table cells. This is a known, general limitation of text-based PDF extraction for tables, distinct from the duplication issue above, and does not affect the presence or correctness of any individual value.
- Devanagari script has visually similar conjunct characters (e.g. ब/व, ल/ला, ट/ड) which are a common OCR confusion source; called out in error analysis.

- Field schema note: owner_names and buyer_names are arrays rather than fixed single/second fields, since the number of parties on a sale deed varies document to document (docB has 4 owners, docA has 2, for example) and a fixed schema would not scale to documents with more parties.
- Field schema note: village, tehsil, and district are kept as three separate atomic fields rather than one combined field, so that field-level evaluation can identify exactly which administrative unit (if any) an OCR error affects.
